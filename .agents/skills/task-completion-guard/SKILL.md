# Task Completion Guard

## Workflow

1. 先区分当前阶段：分析、实施、验证、收尾。
2. 只有真实修改、命令、检查或产物发生后，才汇报为已完成。
3. 如果只完成方案或部分探索，明确说明仍停留在哪个阶段。
4. 执行修改后，至少做一次自检：用户最初要求是否真正落地。
5. 最终回复说明已完成项、未完成项、验证情况和残留风险。

## Self Check

- 用户要的是方案，还是实际修改。
- 当前是否还有未做完的文件、文档或校验。
- 是否把“下一步要做”误说成“已经完成”。
- 是否需要同步 `project-directory-structure.md` 或 `project-quick-brief.md`。
